# Quantum Random Generator

A static Polish-language web app that draws numbers and people from a pool
generated by an IBM Quantum backend.

## Project layout

- `docs/` - deployable GitHub Pages site.
- `generator/` - Python CLI that generates and atomically publishes
  `docs/random.json`.
- `.github/workflows/` - scheduled generation and Pages deployment.

## Local development

Serve `docs/` from a local HTTP server (the app uses `fetch`, so opening
`index.html` directly is not supported):

```powershell
python -m http.server 8000 --directory docs
```

Then open <http://localhost:8000>.

## Generating a pool

Install the pinned dependency ranges and provide IBM Quantum credentials:

```powershell
python -m pip install -r generator/requirements.txt
$env:IBM_TOKEN = "your-token"
$env:IBM_INSTANCE = "your-instance"
python generator/generate_random.py
```

The generator accepts `--pool-size` and `--output`. The equivalent environment
variables are `POOL_SIZE` and `OUTPUT_PATH`. It validates the backend response
and writes the JSON through a temporary file to avoid publishing partial data.

## Deployment

The scheduled workflow requires the repository secrets `IBM_TOKEN` and
`IBM_INSTANCE`. GitHub Pages must be configured to use GitHub Actions as its
build and deployment source.

The published pool contains 100 values by default and is a finite cache.
The values remain in the order generated by IBM Quantum. On every click, the
browser consumes the next value from the local pool using JavaScript's
`pop()` function. The value is then mapped to the selected number range or
participant list. When the pool is exhausted, run the generation workflow
again to publish a fresh pool.

This means every result is based on a value generated by the quantum
computer. The static site does not contact IBM Quantum directly; it consumes
the published pool, which keeps IBM credentials off the client.
